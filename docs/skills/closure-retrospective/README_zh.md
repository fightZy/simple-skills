# 收尾上下文优化

本文档面向维护者，不参与运行时加载。权威入口是 [SKILL.md](../../../.agents/skills/closure-retrospective/SKILL.md)。

## 用途与范围

基于已有工作证据，改善长期指导及其支持的后续决策。保留、删除、合并、澄清、缩小范围、调整位置和补充内容都是有效结果。通用的是判断方法，每条建议仍应受其证据和适用范围约束。

默认在非平凡任务收尾时使用。用户明确要求复盘或审阅上下文时，也可以检查已有稳定证据的工作单元，即使其他工作尚未完成。未完成的诊断只限制依赖它的结论；复盘不接管未完成的工作，也不补做领域实验。

以当前任务为锚点，只在必要且符合既有访问权限和任务范围时引用相关、可追溯的历史证据。本技能不压缩会话；除非用户明确要求，不把输出转入记忆流程。

## 判断流程

1. 识别有证据支持的上下文问题，说明修改可以改善哪个后续决策。一次失败本身不足以支持增加指导。
2. 检查已有指导、权威来源和加载时机。已有覆盖可以排除重复添加，同时仍允许有价值的清理。
3. 先判断适用范围和加载时机，再选择最小有效改动及其确切位置。
4. 只对重要未决问题或适用的复核要求进行独立复核，分别记录证据不确定性、派发授权和可用能力。
5. 提出与问题规模相称的建议，说明证据、边界、收益、成本，以及必要时重新审视的条件。

只有独立可调用的工作流才考虑新建技能。项目指导应放在对应的适用范围内，文件类型之间没有固定优先顺序。

## 批准与输出

编辑前先提出具体建议。已批准的范围授权相应修改和适当校验，无须重复确认同一范围。派发子代理复核需要用户明确要求或项目既有授权。

零条或一条建议足够时保持简短，不设凑数要求或固定上限。没有合格建议时，用户明确要求复盘就简要解释原因，否则正常结束，不额外输出复盘部分。

如果指导依赖会变化的工具、环境、流程或分工，应说明什么变化会使它失效或需要重新审视。记录这个条件不会启动持续监控。

## 验证

仓库检查覆盖安装包布局和说明文档入口。格式与引用检查只能证明结构有效，不能证明后续任务的决策已经改善。应分别报告实际修改、完成的检查与观察到的行为效果。

# 收尾上下文优化

本文档面向维护者，不参与运行时加载。权威入口是 [SKILL.md](../../../.agents/skills/closure-retrospective/SKILL.md)。

## 用途与范围

基于已有工作证据，优化 agent 获取、发现、理解和使用上下文及执行反馈的环境。修改对象可以是指导语或相关环境机制，保留、删除、合并、澄清、缩小范围、调整位置和补充内容都是有效结果。通用的是判断方法，每条建议仍应受其证据和适用范围约束。

默认在非平凡任务收尾时使用。用户明确要求复盘或审阅上下文时，也可以检查已有稳定证据的工作单元，即使其他工作尚未完成。未完成的诊断只限制依赖它的结论；复盘不接管未完成的工作，也不补做领域实验。

以当前任务为锚点，只在必要且符合既有访问权限和任务范围时引用相关、可追溯的历史证据。环境机制的审查限于它对上下文使用或执行反馈的影响，普通业务工作仍由原任务负责。本技能不压缩会话；除非用户明确要求，不把输出转入记忆流程。

## 判断流程

1. 围绕待解释的结果或决策确定复盘范围，包括能够完整解释它的最小决策跨度和外部证据边界。最终状态不足以解释原因时，只追溯可能改变结论的上游上下文。
2. 识别有证据支持的环境上下文问题，说明修改可以改善哪个后续决策或执行结果。观察举例是可选、非穷尽的入口，候选仍按证据与问题机制筛选。一次失败本身不足以支持长期变更。
3. 检查已有指导、信息来源、工具或反馈机制的权威性、可用时机、可操作性、接入情况、一致性和流程交接。存在合适文字或机制本身不能证明只是执行问题。
4. 先判断支持的范围，并按问题机制选择补救方式，再确定归属、加载或激活时机及最小有效改动。
5. 只对重要未决问题或适用的复核要求进行独立复核，分别记录证据不确定性、派发授权和可用能力。
6. 提出与问题规模相称的建议，说明证据、边界、收益、成本，以及必要时重新审视的条件。

只有独立可调用的工作流才考虑新建技能。指导语和环境机制应放在对应的适用范围内，根据问题机制及预期收益选择补救方式，不固定偏好某种文件类型、文字或自动化。

## 批准与输出

应用变更前先提出具体建议。已批准的范围授权相应修改和适当校验，无须重复确认同一范围。派发子代理复核需要用户明确要求或项目既有授权。

零条或一条建议足够时保持简短，不设凑数要求或固定上限。没有合格建议时，用户明确要求复盘就简要解释原因，否则正常结束，不额外输出复盘部分。

如果变更依赖会变化的工具、环境、流程或分工，应说明什么变化会使它失效或需要重新审视。记录这个条件不会启动持续监控。

## 验证

仓库检查覆盖安装包布局和说明文档入口。格式与引用检查只能证明结构有效，不能证明后续任务的决策或执行已经改善。应分别报告实际修改、完成的检查与观察到的行为效果。
